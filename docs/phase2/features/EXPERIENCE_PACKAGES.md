## Shared implementation rules for every package

- Java base path is `backend/src/main/java/com/app/sme_health_backend/`; frontend base path is `frontend/src/`. Extend the current package-by-domain structure, `SessionProvider`, `apiClient`, authorization, audit and exception systems.
- New HTTP examples use `/api/v2`; frontend `apiClient` takes `/v2/...` because it already prefixes `/api`. Existing `/api` endpoints and numeric DTOs remain compatible. C12 (B, A review) defines the final wire schema; proposed new monetary values are decimal strings plus ISO currency, UUID references, ISO local dates/UTC instants, explicit nulls and enums. Do not convert financial strings through JavaScript Number for accounting.
- Request bodies never choose business/user identity. Server active business and authenticated membership determine scope, including referenced document/project/obligation ownership and A's future salesperson row scope. Changing business, revoking access or disabling a module must invalidate eligible caches/results immediately. Server enforcement must precede client hiding.
- Proposed write DTOs include optimistic `version` where state can conflict. Repeated create/transition commands use a server-scoped idempotency key with payload hash where duplication matters. HTTP errors distinguish validation 400, authentication 401, forbidden/module-disabled 403, absent or inaccessible references 404, state/version/idempotency conflicts 409, rate limits 429 and upstream failure 503. Exact envelopes are governed by C12, not independent per-feature inventions.
- Proposed reads return values plus `currency`, `asOf`, period, source mode, completeness, source/evidence references and explicit unavailable/restricted/stale reasons where applicable. A null value is not a zero, and a forecast/planned value is not actual. Exports and AI consume the same authoritative service DTOs as screens.
- New permission names below are proposals for extending `identity/model/BusinessPermission.java` and the frontend role map together. A reviews their grants and row scope. No feature silently grants new finance powers to manager/viewer/salesperson or relies solely on module visibility.
- Migration identifiers are deliberately **unallocated**. Reserve the next free Flyway version in the shared state before implementation; never edit V1–V17 or claim a future V-number while A may be using it. Each schema proposal needs fresh and upgrade-path PostgreSQL tests, indexes, tenant constraints and rollback by feature disable where safe.
- Financial policy affecting revenue/cash/COGS/commission/FX/recognition requires both A/B approval in an ADR. Example equations below specify a design candidate or reconcile existing authoritative values; they are not permission to post financial events. C01/C02/C04/C06/C08/C09/C11 remain owned according to the final division, especially C08 = A.
- Every vertical slice includes typed EN/UR text (including ARIA/error messages), RTL, keyboard operation, mobile states, loading/empty/partial/permission/error UI, deterministic fixtures, server tenant/security tests and a real authorized frontend/backend journey. Synthetic browser and mocked-provider tests are separately labelled.
